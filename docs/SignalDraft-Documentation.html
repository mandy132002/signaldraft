1. Product overview

SignalDraft helps an SDR research a named person at a named company and produce a real first-touch email grounded in a checkable public hook. The output is the email the SDR would send — not a pitch for SignalDraft itself.

Core promise:

  • Live process, not a mock — Wikipedia, Google News RSS, Hacker News, Groq.
  • Exact person + company — lookalikes and other-employer news are rejected.
  • Human in the loop — approve / reject / refine; nothing is auto-sent.
  • Prefer a hold over a wrong email — if no confirmed hook exists, hold.

Surfaces in the app:

Live run/One prospect → research stages → draft → review
Bulk/bulkCSV upload, sequential research, review queue
Dashboard/historySaved runs, KPIs, edit / approve / Gmail
Login/loginGoogle sign-in via Auth.js

2. Problem statement

An SDR enters prospect details (e.g. Jeff Bezos at Amazon) and needs an outreach email that cites a relevant public hook. Research is slow and error-prone when company names collide (Cube Global vs Cube Logic) or when the person appears under another employer (Bezos / Blue Origin while researching Amazon).

SignalDraft automates:

  1. Public signal gathering
  2. Exact-name ranking and Groq entity confirmation
  3. Sentiment / impact analysis
  4. A short cold email for human review

4. Research & draft pipeline

StageWhat happens
IntakeValidate name + company; capture LinkedIn / notes / offer
Company + LinkedInWikipedia snapshot (quoted exact name); optional LinkedIn context
News & fundingGoogle News RSS (quoted company + soft tokens + offer themes)
Person signalsPerson + company queries; HN (full company phrase)
Soft-rankScore exact / soft / suspect / person; drop junk & stale items
Groq entity matchLLM confirms which candidates are the right org / person
Groq analysisSentiment, business impact, outreach angle, risk flags
DraftShort cold email + Low / Medium / High confidence
ReviewEdit, refine, approve/reject, optional Gmail draft — not sent

Matching rules (summary)

  • Multi-word companies are never shortened to the first token (no “Cube” for Cube Global).
  • A sendable hook must contain the exact company phrase.
  • Person-only stories about another employer cannot be the primary hook.
  • After Groq, a safety net drops “matches” missing the exact company name.

5. Features by surface

Live run (/)

  • Intake form (prospect, company, LinkedIn, sender, offer, notes).
  • Live stage timeline with per-step durations.
  • Signals list with match tier, eligible flag, sensitive flag.
  • Groq entity note + analysis cards.
  • Editable subject/body, Refine prompt, Approve / Reject, Gmail button.
  • Hold and sensitive callouts when applicable.
  • Session restore when switching to Dashboard and back.

Bulk (/bulk)

  • CSV template download; required columns: fullName (or name), company.
  • Optional: title, linkedinUrl, notes.
  • Up to 40 rows; processed one at a time.
  • Review queue with Approve / Reject / Gmail; Resume if a batch times out on Vercel.

Dashboard (/history)

  • KPIs: Runs, Emails stored, Needs review, Approved.
  • Loading skeletons (no flash of 0 / 0 / 0) while fetching.
  • Search, select a run, edit, store decision, copy, Gmail.
  • Shows draft confidence badge and reason.

6. Edge cases

Full detail also lives in docs/EDGE_CASES.md. The pipeline prefers a hold over inventing or guessing the wrong company.

6.1 Lookalike company names

Example: Cube Global vs CUBE / Cube Logic / Black Cube.

  • Search and match the full quoted company phrase.
  • looksLikeWrongCompany flags near-misses.
  • Post-LLM safety net drops matches without the exact phrase.
  • HN searches the full name, not the first token.

6.2 Person–company split

Example: Jeff Bezos / Amazon vs Blue Origin news.

  • First and last name must appear near each other.
  • Sendable hook must name the target company.
  • If only other-employer stories exist → hold.

6.3 No confirmed public hook

Example: Low-coverage company with no exact-name news.

  • Internal hold note (HOLD — do not send), not a fake outreach email.
  • Gmail and Refine disabled; Store hold still allowed for tracking.

6.4 Sensitive / negative news

Example: Layoffs, lawsuit, death, bankruptcy, data breach.

  • Prefer a non-sensitive exact-company hook when one exists.
  • Otherwise: sober tone, risk flags, confidence capped at Medium, UI caution banner.

Residual risks

  • Single-token brands (Apple, Delta, Meta) can still collide — prefer legal names.
  • Very common names need a LinkedIn URL for safer identity.
  • Hooks older than ~18 months are dropped.

7. Draft confidence

Groq rates each drafted email as Low, Medium, or High, with a one-line reason shown in Live, Dashboard, and Bulk.

RatingMeaning
HighHook clearly names this person or exact company; facts are in the research pack; offer bridge is natural
MediumCompany match is solid but the hook is thin/older or the offer link is inferred
LowWeak, stale, or sensitive hook — or no confirmed entity (hold)

Caps: sensitive hooks and auto-rewritten drafts cannot stay High. Holds stay Low. Heuristic fallbacks (if Groq draft fails) use hook strength, not a model self-rating.

Groq entity check reliability

Entity check runs on Groq. The default model openai/gpt-oss-20b is a reasoning model; earlier empty replies were caused by a small token budget spent on internal reasoning. Current client uses a larger max_completion_tokens budget, low reasoning effort, and fallbacks to other Groq models when the first reply is empty.

8. Local setup

8.1 MongoDB Atlas

  1. Create a free cluster at cloud.mongodb.com.
  2. Database Access → user + password.
  3. Network Access → allow 0.0.0.0/0 (or your IPs) for local + Vercel.
  4. Copy the mongodb+srv://… URI; URL-encode special characters in the password.

8.2 Google OAuth

  1. Google Cloud Console → OAuth client ID (Web application).
  2. Origins: http://localhost:3000
  3. Redirect: http://localhost:3000/api/auth/callback/google

8.3 Environment

cp .env.example .env.local

9. Vercel deployment

  1. Push the repo to GitHub; import as a Next.js project on Vercel.
  2. Set the same env vars as local, with AUTH_URL=https://YOUR_PROJECT.vercel.app.
  3. In Google OAuth, add the production origin and callback URL.
  4. Deploy; sign in; run a Live draft.

Production URL used in this project: https://signaldraft-sand.vercel.app. Do not confuse with unrelated Vercel projects on similar domains.

  • Hobby function time limits: Live is fine; large Bulk jobs may need Resume remaining.
  • Atlas must allow Vercel egress (0.0.0.0/0 is simplest for a personal project).

10. Gmail drafts

Login only requests email/profile. Gmail compose is requested later when the user clicks Allow Gmail access / Add to Gmail drafts.

  1. Enable Gmail API in Google Cloud.
  2. OAuth consent: External, Testing; add yourself as a test user; add gmail.compose scope.
  3. Unverified apps show a warning — Advanced → continue (normal for local/test).

Hold notes cannot be saved to Gmail (UI disabled; API rejects). Tokens are persisted in JWT + MongoDB on sign-in so reconnect works under JWT session mode.
